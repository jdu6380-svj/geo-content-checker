# Evidra 求职作品集 Beta 验收标准

更新日期：2026-09-07

## 1. 阶段目标

本阶段将 Evidra 收口为可重复演示、可邀请真实目标用户试用、可形成产品证据的 AI 产品经理求职作品集主项目。

交付形态是免费 Portfolio Beta，不上线真实支付，不要求注册或登录，不建设用户可见的额度、套餐或授权产品。Preview 使用隔离的 interview workspace 保存项目、运行记录和报告；Production 的 Clerk、Neon、支付、正式工作区权限及安全边界继续保留，但不属于本轮验收范围。

## 2. 本轮纳入验收

- 无登录进入 Vercel Preview 工作台。
- 创建内容项目并切换项目。
- 粘贴真实文章，或读取 TXT、Markdown 文件。
- 调用真实 OpenAI-compatible 模型完成评分、五个读者问题、Evidence 诊断和 Patch 修改建议。
- 明确展示排队、分析中、完成、失败、超时、取消和重试状态。
- 保存报告与运行历史，刷新后可以重新查看。
- 复制修改建议、回到正文修改并重新分析。
- 展示前后评分变化，完成“分析—修改—复查”闭环。
- 记录匿名、非敏感的产品与模型指标。
- 保留服务端隐藏安全上限、限流和模型预算，防止 Preview 被无限调用；前端不把它包装成额度产品。
- 桌面端和 390px 移动端核心流程可用。
- 完成类型检查、Lint、测试、构建、黑盒与 Preview smoke 验证。

## 3. 本轮明确排除

- Clerk 登录、注册、组织选择和 onboarding。
- 用户账户级私有报告承诺。
- 用户可见额度、额度申请、Beta grant、套餐与购买入口。
- 支付宝收款、订阅、续费、退款和 Production 支付验收。
- Production Promote 或替换当前 Production。
- PDF、DOCX 原生解析；用户可改为粘贴正文。
- 核心验证完成前的大规模 UI 重构。
- 与求职案例验证无关的新功能。

## 4. 工程验收清单

### 已具备或已完成本地验证

- Preview interview mode 可绕过 Clerk，Production 不绕过鉴权。
- 项目、运行历史、报告读取、修改建议和重新分析链路已有实现。
- Preview Redis 持久化存在；Redis 不可用时有内存回退。
- 支付和商业工具在 Portfolio Beta 界面隐藏。
- 旧匿名模型接口继续保持迁移拒绝边界。
- 支付、Clerk、Neon 商业路径代码继续保留。

### 发布前仍需真实验证

- Preview 页面无需公开环境变量也能稳定进入 Portfolio Beta 表现层。
- Preview 不出现登录、用户身份、套餐、购买、支付或用户可见额度表达。
- OpenAI-compatible 服务在受控 Preview 返回 `source: "model"`，不能把 deterministic fallback 作为模型质量证据。
- Redis 可用时，项目、运行记录和报告能够跨请求、刷新和新页面恢复。
- 模型失败、无效输出、超时、取消和结果读取失败不会被显示为成功。
- 内部安全上限生效，但页面只显示安全运行限制，不引导购买或申请额度。
- 日志、Sentry 和匿名指标不记录正文、Prompt、Evidence 原文、密钥、Token、Cookie 或身份原值。
- 无登录 Preview 不会使旧匿名分析接口或 Production 商业接口失去原有保护。
- 桌面端和 390px 移动端完成一次完整黑盒流程。

## 5. 产品验证标准

以下结果必须来自真实执行，禁止编造：

- 建立不少于 20 条人工评测样本，覆盖不同内容类型、风险强度和证据状态。
- 邀请 10–15 名目标用户参与试用。
- 累计完成 30–50 次真实模型分析。
- 至少 5 名用户完整走通“分析—采纳或修改—复查”闭环。
- 记录完成率、模型成功率、平均耗时、估算单次成本、Evidence 判断准确性、建议采纳率和复查完成率。
- 收集用户对报告可理解性、建议可执行性和继续使用意愿的反馈。
- 根据真实数据和访谈完成两轮有证据的迭代，并保留问题、假设、改动和结果记录。

## 6. 作品集停止条件

同时满足以下条件后停止增加功能，转入 UI 精修、案例文档、演示视频和个人作品集网站：

1. Preview 核心闭环稳定，刷新和历史恢复可重复验证。
2. 真实模型、失败状态、安全边界和隐私记录通过验收。
3. 人工评测与真实用户证据达到最低样本量。
4. 两轮迭代有可展示的决策依据和前后变化。
5. 五分钟演示可连续重复完成，并能清楚解释产品问题、用户、方案、指标、取舍和下一步。

## 7. 当前剩余主线

1. 完成 Portfolio Beta 界面与状态收口，并跑全量工程检查。
2. 推送新 Preview，验证真实模型、Redis 持久化、安全上限和错误状态。
3. 完成桌面端与 390px 移动端 smoke。
4. 建立 20 条人工评测集并执行基线评测。
5. 招募目标用户，完成 30–50 次真实分析与至少 5 次完整复查闭环。
6. 基于证据完成两轮迭代。
7. 最后进行 UI 精修和求职案例包装。
