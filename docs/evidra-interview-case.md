# Evidra 项目案例（作品集版）

## 一句话介绍

Evidra 是一个面向内容团队的 AI 内容可信度审查工作台：在内容发布前，将评分、读者问题、证据缺口与可执行的编辑建议组织成一份可复查报告。

## 要解决的问题

内容团队在发布前通常依赖人工经验检查文章是否讲清楚、有没有依据、能否回应读者问题。这个过程不稳定，也难以向编辑、客户或负责人说明“为什么要改”。

Evidra 不承诺排名或自动改稿，而是让审查过程可追溯：

- 用结构化维度评估内容的覆盖度、事实完整度、结构和时效性。
- 预测读者会提出的关键问题。
- 标出需要补证据或补充边界条件的内容。
- 生成低风险的编辑提纲，帮助人工完成修改并复查。

## 面试演示路径

1. 进入“面试项目演示”，展示已认证工作区与邀请制 Beta 额度。
2. 打开一份已完成报告，先讲评分和“待处理项”。
3. 展开“读者问题”，说明产品不是泛化点评，而是把发布风险转换成需要被回答的问题。
4. 展开“Patch 建议”，说明建议只包含补充证据和调整结构，不会自动编造事实或直接替用户改稿。
5. 说明修改后可再次提交，形成“分析 -> 编辑 -> 复查”的内容质量闭环。

建议使用一篇 800 至 1,500 字、有明确事实或案例的中文文章演示。短文本只适合功能冒烟，不适合证明产品价值。

## 产品设计要点

| 决策 | 原因 | 呈现方式 |
| --- | --- | --- |
| 先展示评分与待处理项 | 编辑需要先知道是否值得继续审查 | 报告顶部的评分卡与三个摘要信号 |
| 问题与建议采用可展开区域 | 避免报告首屏被长文本淹没 | 默认展示摘要，按需阅读详情 |
| 将建议限定为“编辑方向” | 防止 AI 越界生成未经验证的事实 | 清晰标注不会自动改写原文 |
| 运行记录与额度服务端保存 | 让试用、复查与用量具有真实状态 | 工作区项目、已完成报告和 Beta 用量 |
| 模型暂时不可用时安全降级 | 演示和 Beta 不因供应商瞬时问题中断 | 明确标记为“结构化诊断”，不伪装成模型结果 |

## 技术与产品边界

- Next.js、Clerk、Neon、Vercel Preview 与 OpenAI-compatible 模型服务。
- 运行按工作区隔离；私有报告不暴露 Blob key。
- 配额通过服务端预留与结算，失败的运行释放额度。
- 模型输出要经过结构校验与 Evidence 约束；不合格输出不会作为可信报告展示。
- Preview 对供应商超时使用确定性、可标识的安全降级；Production 仍保持失败关闭。

## 当前阶段与下一步

当前版本是面试演示型邀请制 Beta，核心闭环已可用。下一步是邀请少量真实内容创作者测试：记录他们是否认可 Evidence、是否采用 Patch、修改后是否愿意复查和继续使用。支付、公开获客和 Production 扩量不是当前面试版本的优先事项。
