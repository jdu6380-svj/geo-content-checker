# Evidra Portfolio Beta 人工评测指南

更新日期：2026-09-07

## 目的

这套评测用于回答三个求职案例核心问题：Evidra 能否发现真正影响内容可信度的问题，Evidence 判断是否可靠，修改建议是否足够具体。它不用于证明商业成果，也不能替代真实用户 Beta。

评测语料位于 `scripts/fixtures/portfolio-beta-evaluation-corpus.json`。20 条内容均为合成样本，不含真实用户正文、客户信息或业务结果。

## 执行前检查

运行：

```bash
npm run portfolio:eval:validate
```

校验通过只代表样本数量、分类、风险分布和人工参考字段完整，不代表模型已经通过质量门禁。

## 单条样本的人工评分

每条样本在同一个 Preview 版本上执行一次完整分析。评审者只能根据报告内容和样本参考答案打分，不读取 Prompt 或模型内部日志。

| 维度 | 0 分 | 1 分 | 2 分 |
| --- | --- | --- | --- |
| 主要问题识别 | 未识别或方向错误 | 识别到相关问题但不完整 | 准确识别 `primaryIssueCode` |
| Evidence 状态 | 与参考明显冲突 | 部分状态合理 | 状态落在 `acceptableEvidenceStatuses` 且解释成立 |
| Evidence 定位 | 虚构或引用无关内容 | 定位大致相关但范围不准 | 引用可以在正文中逐字定位且支持判断 |
| 修改建议 | 不可执行或引入新事实 | 有方向但仍需大量补充 | 明确说明补什么、删什么或如何降级结论 |
| 风险表达 | 夸大、承诺或误导 | 风险级别可接受但理由弱 | 风险级别与内容场景一致并保留边界 |

单条满分 10 分。任何虚构 Evidence、把明显冲突判断为有效、或对医疗/金融高风险内容给出确定性背书，直接标记为严重失败，不能被平均分抵消。

## 必记字段

- 样本 ID、Preview deployment ID 和运行时间。
- 模型来源是否为 `model`。
- 是否成功生成完整报告。
- 总耗时与可获得的 Token/成本摘要。
- 五个维度的 0–2 分。
- 是否出现严重失败。
- 评审者匿名编号。

禁止记录正文副本、Prompt、Evidence 原文、Cookie、Token、密钥、用户身份或供应商原始错误。

## 第一轮门槛

- 20 条样本全部执行，不用失败样本替换难例。
- 模型来源成功率至少 95%。
- Evidence 可逐字定位率 100%。
- Evidence 语义判断准确率高于 90%。
- 修改建议可执行性至少 90%。
- 严重失败为 0。

未达到门槛时记录失败类型，优先修复系统性问题，再使用同一 20 条样本复测。不能删除失败样本或修改参考答案来提高结果。

## 与真实用户 Beta 的关系

人工评测通过后，才进入 10–15 名目标用户、30–50 次真实分析和至少 5 次完整复查闭环。合成评测结果描述模型质量，真实用户结果描述产品价值，两类证据必须分开呈现。
